# Chrome 会话生命周期审查与修复

范围：接续原会话 `391fff45-076a-434a-8a7c-b2fb228fa66b` 中因额度中断的 `bb70d37..5f5f1d1 --fix`。本轮为主线程源码审查、定向复现与修复，未重启历史多代理任务，也不声称是独立多人复核。

## 核实的问题与处理

| 触发条件及影响 | 证据与修复 |
|---|---|
| 终端仍在运行，但网关时钟前跳且心跳尚未续约，空闲实例被回收；两端 heartbeatSec 不一致也会让租期短于续约间隔。 | 原基线的时钟前跳用例失败。改用一条持续 HTTP 连接表示会话存活，时间前跳不会过期；旧心跳接口保留，新旧版可交错升级。兼容心跳可携带自己的 TTL。 |
| shim 被强杀时无法发送 `/session/end`，页面继续滞留到空闲回收。该退出缺口在本次被审范围之前已存在。 | 原基线强杀用例失败；新版用真实进程/套接字断开回收，并覆盖正常退出、父进程死亡、后端冷启动期间退出、连接替换及清理期间重连。共享实例不随某个 owner 退出而关闭。 |
| 起始页通过脚本写入内容但 URL 未变，后续 new_page 覆盖原内容。由 `5f5f1d1` 引入。 | 隔离 Chrome 上旧版内容保留两项检查失败，新版通过。单独记录页面是否被使用；纯观察工具仍允许首次开页复用空白页。 |
| 会话页面主线程繁忙时，Ctrl+点击开页超时后回退到原生 new_page，可落到其他窗口。回退在早期窗口实现中已存在，移除空白占位页后更易暴露。 | 用有时长上限的繁忙脚本复现旧版创建成功并出现目标页；新版 5 秒后明确报错且目标页不存在，避免跨会话回退。参见下方浏览器对照日志。 |
| heartbeatSec 超出 Node 定时器范围时被折回很短的间隔。 | 将值限制在有效范围，非法/非有限值回到默认值；配置回归覆盖边界。 |

保留了“每终端一个窗口，终端在则默认保留”的要求。未采纳默认 12 小时强制关闭建议；没有把代码重复或样式偏好当作运行缺陷。

## 适用边界

时钟前跳是定向模拟休眠恢复后的过期时序，没有让本机真实休眠；没有做完整 15 分钟以上的线上保留观察。旧终端仍持有旧 shim，需要重开后才使用持续连接。父进程 PID 复用加泄漏 stdin 的复合情形未端到端复现；未用永久保留或定时强关的相反策略掩盖它。原有 isolatedContext 行为保持，未新增其隔离语义验收。
